# 用户画像策略

## 画像字段

- 当前 Skill 使用者身份：程序员、产品经理、运营、内容创作者、创业者、企业老板、销售、咨询顾问、投资/研究人员等。
- 当前 Skill 使用目的：找项目做产品、找内容选题、做商业调研、找客户方案、做竞品分析、找学习案例、寻找投资/合作机会等。
- 用户类型：基于身份和目的综合判断，例如独立开发者、AI 工具站运营者、内容创作者、企业服务创业者、课程制作者、业务负责人、商业分析者等。
- 技术能力：无代码、低代码、前端、全栈、AI 工程、后端基础设施。
- 时间预算：1 天、3 到 7 天、2 到 4 周、长期投入。
- 资金预算：无预算、低预算、中等预算、可采购 API 或服务器。
- 目标产出：内容选题、MVP 工具、SaaS、插件、小程序、课程案例、企业方案。
- 目标市场：中文个人用户、中文企业用户、海外开发者、垂直行业。
- 内容平台：小红书、抖音、公众号、B 站、知乎、海外社区。
- 变现偏好：订阅、按次付费、模板售卖、咨询定制、内容引流。
- 风险偏好：保守、中等、进取。

## 必达问题优先级

用户画像阶段必须优先补齐以下字段：

1. `project_direction`：项目方向。
2. `skill_user_identity`：当前使用 Skill 的人是谁。
3. `skill_user_goal`：当前使用 Skill 的目的是什么。
4. `target_user`：最终产品或服务的目标付费用户。
5. `target_output`：最终产品形态。
6. `mvp_time_budget`：MVP 时间预算。
7. `payment_goal`：收费方式或商业验证目标。
8. `technical_level`：用户可承担的技术复杂度。
9. `risk_boundary`：明确不碰的风险边界。

这些字段缺失时，不得直接进入 GitHub 搜索。可以从用户原话中推断，但必须在画像摘要中标注来源为 `user_provided`、`inferred` 或 `defaulted`。其中必达问题不允许只用 `defaulted` 作为最终依据，除非用户明确授权继续按默认假设执行。

## 推断规则

- 用户强调“快速上线”“日报”“工具站”时，默认偏向低成本 Web 工具和内容传播。
- 用户强调“小红书”“抖音”“公众号”时，提高内容传播权重。
- 用户强调“企业客户”“私有化”“解决方案”时，提高企业服务和合规权重。
- 用户强调“找客户方案”“给客户交付”时，默认报告偏业务包装、实施路径和报价逻辑。
- 用户强调“做调研”“投资”“合作机会”时，默认报告偏市场判断、风险和项目成熟度。
- 用户没有说明当前 Skill 使用者身份时，必须先问，不默认他是程序员。
- 用户没有说明技术能力时，必须结合当前 Skill 使用者身份判断；非技术用户应优先推荐低代码、托管、模板化或外包可执行方案。

## 默认画像

当信息不足但任务仍可继续时，使用以下默认：

- 用户类型：独立开发者 / AI 工具站运营者
- 目标市场：中文市场
- 技术能力：可完成基础 Web 应用和 API 接入
- 时间预算：3 到 7 天
- 风险偏好：中等偏保守

默认画像只适用于非必达字段。必达字段缺失时，先问用户，不直接默认。
