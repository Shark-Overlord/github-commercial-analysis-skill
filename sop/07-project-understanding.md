# 07 项目真实用途理解

## 目标

在评分之前，先用证据解释项目真实用途，避免凭项目名称或 Star 数主观判断。

## 必读资源

- `prompts/project-analysis-prompt.md`
- `schemas/project-info-schema.json`

## 判断问题

- 项目解决什么问题？
- 面向什么用户？
- 用户输入什么？
- 系统输出什么？
- 核心功能链路是什么？
- 它是工具、平台、框架、模型、插件还是完整应用？
- 普通用户是否能理解？
- 是否有可视化展示价值？
- 是否适合包装成中文产品？

## 执行步骤

1. 先读取结构化信息和 README 摘要。
2. 用 3 到 5 句话解释项目真实用途。
3. 提取项目的“可包装卖点”和“难以包装的部分”。
4. 判断该项目是面向开发者、普通用户、企业用户还是内容创作者。

## 输出

每个项目输出：

- 一句话定义
- 核心用户
- 核心场景
- 输入输出
- 可包装卖点
- 包装障碍

## 质检

- 不要把底层库误判成可直接面向普通用户的产品。
- 不要忽略开发者工具在中文市场中的二次包装价值。
