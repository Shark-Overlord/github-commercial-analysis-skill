# 项目筛选策略

## 保留条件

- 项目用途清晰。
- 最近 180 天有维护迹象。
- README 能说明安装、使用或场景。
- 有明确用户痛点或效率提升。
- 不属于明显违法、攻击、钓鱼、破解或隐私侵犯用途。

## 降级条件

- Star 高但 README 不清晰。
- 技术价值高但普通用户难理解。
- License 缺失或商用边界不清。
- 部署复杂但可通过托管服务降低门槛。
- 市场价值可能存在，但需要更多验证。

## 排除条件

- 明确用于恶意攻击、破解、绕过限制、窃取数据或垃圾信息。
- 长期无人维护且依赖严重过期。
- 只有论文复现，没有可包装用户场景。
- 复刻成本明显超过用户时间和预算。

## 排序原则

最终排序优先看：用户匹配度、商业化潜力、MVP 可行性、风险可控性、内容传播价值。
