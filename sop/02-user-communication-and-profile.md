# 02 用户沟通与画像建立

## 目标

在数据源配置完成后，先明确当前使用这个 Skill 的人是谁、他使用 Skill 的目的是什么，再明确他能投入什么、想得到什么结果。用户画像会影响搜索关键词、项目筛选、评分权重、MVP 建议和最终推荐等级。

## 必读资源

- `strategies/user-profile-strategy.md`
- `criteria/user-profile-criteria.md`
- `schemas/user-profile-schema.json`

## 执行步骤

1. 先检查“必达问题”是否已经由用户明确回答，或是否能从上下文可靠推断。
2. 对缺失的必达问题，必须先向用户补问；不得在必达问题缺失时直接进入项目搜索。
3. 收集用户的技术能力、可投入时间、预算、目标市场、目标产出、内容平台、变现偏好和风险承受能力。
4. 如果用户已经给出上下文，先从上下文中提取画像，不重复询问已明确的信息。
5. 非必达信息缺失时，可以采用最小化默认假设继续分析，并在报告中标注。
6. 将画像整理为结构化对象，字段参考 `schemas/user-profile-schema.json`。
7. 当用户明确说“重新开始”“重新测试”“忘记之前的画像/记忆”时，必须把本轮视为全新画像采集；不得复用 `data/processed/fresh-user-profile.json`、旧日报或旧缓存中的画像结论。
8. 自动化脚本只能在用户本轮回答后读取 `data/config/current-user-profile.json` 作为画像输入；如果该文件不存在或必达字段缺失，必须停止执行并输出补问清单。

## 必达问题

以下问题必须有答案。答案可以来自用户原话，也可以来自上下文中的明确推断；如果不能确定，必须先问用户。

| 问题 ID | 必达问题 | 为什么必须问 |
| --- | --- | --- |
| `skill_user_identity` | 当前使用这个 Skill 的人是谁？例如程序员、产品经理、运营、内容创作者、创业者、企业老板、销售、咨询顾问、投资/研究人员。 | Skill 不只服务程序员，使用者身份会影响分析深度、输出语言和推荐项目类型。 |
| `skill_user_goal` | 这个人使用 Skill 的目的是什么？例如找项目做产品、找内容选题、做商业调研、找客户方案、做竞品分析、找学习案例、寻找投资/合作机会。 | 决定最终报告是偏落地执行、内容传播、商业判断还是研究决策。 |
| `project_direction` | 你想找什么方向的 GitHub 项目？例如 agent、RAG、浏览器自动化、图片工具、数据分析。 | 决定搜索关键词和项目范围。 |
| `target_user` | 最终产品或服务卖给谁？例如个人用户、独立开发者、中小企业、运营人员、教育机构。 | 决定商业化包装和付费理由。 |
| `target_output` | 你要做成什么形态？例如 Web 工具站、SaaS、小程序、浏览器插件、API、课程案例。 | 决定筛选项目和 MVP 形态。 |
| `mvp_time_budget` | 你希望多久做出 MVP？例如 1 天、3-7 天、2-4 周。 | 决定项目难度上限。 |
| `payment_goal` | 你希望怎么收费？例如按次付费、订阅、模板售卖、部署服务、企业定制。 | 决定是否适合“带支付”的产品。 |
| `technical_level` | 你能承担什么技术复杂度？例如只会部署、会前后端、会 Python/Node、能接模型 API。 | 避免推荐无法落地的项目。 |
| `risk_boundary` | 有哪些不碰的风险边界？例如爬虫、账号自动化、金融交易、隐私数据、License 不明项目。 | 决定风险过滤和是否允许输出复刻路线。 |

## 提问方式

- 一次只问真正缺失的必达问题，避免重复问用户已经说过的内容。
- 如果用户只给出简短需求，优先用 5 到 7 个短问题补齐画像。
- 如果用户没有回答非必达问题，可以用默认假设继续，但必须在报告中标注。
- 如果用户没有回答必达问题，不得生成采集任务。
- 如果用户要求重新测试 Skill，先重新询问必达问题，再生成新的采集任务；不得沿用上一次分析中的用户画像。

## 输出

输出一份用户画像摘要，至少包含：

- 用户类型
- 当前 Skill 使用者身份
- 当前 Skill 使用目的
- 目标市场
- 目标产出
- 技术能力
- 时间预算
- 预算水平
- 内容平台
- 变现偏好
- 风险偏好
- 必达问题回答来源
- 默认假设

## 质检

- 不允许在没有画像的情况下直接推荐项目。
- 不允许在必达问题缺失时进入采集任务。
- 默认假设必须显式写入最终 HTML 报告。
- 画像描述要服务于后续筛选，避免写成泛泛的人物介绍。
