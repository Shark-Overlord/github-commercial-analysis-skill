# 用户画像判断标准

## 当前 Skill 使用者身份

- 程序员 / 独立开发者：可以接受代码级实现、部署、API 接入和工程风险说明。
- 产品经理 / 运营 / 内容创作者：输出应减少代码细节，强调产品形态、用户场景、内容传播和商业验证。
- 创业者 / 企业老板：输出应强调市场机会、投入产出、团队配置、风险和落地路径。
- 销售 / 咨询顾问：输出应强调客户痛点、方案包装、报价方式和交付边界。
- 投资 / 研究人员：输出应强调赛道趋势、项目成熟度、竞争格局和风险判断。

## 当前 Skill 使用目的

- 找项目做产品：优先推荐 3-7 天或 2-4 周可验证的项目，并给 MVP 和支付路径。
- 找内容选题：优先推荐演示效果强、标题好讲、适合截图录屏的项目。
- 做商业调研：优先输出市场判断、竞品关系、风险和机会排序。
- 找客户方案：优先输出可交付服务包、报价逻辑和实施边界。
- 找学习案例：优先输出技术价值、学习路径和复刻难度。

## 技术能力

- 1 分：无代码能力，只能使用现成工具。
- 2 分：能使用低代码、部署简单模板。
- 3 分：能完成基础前端、后端或 API 接入。
- 4 分：能完成完整 Web 应用和第三方服务集成。
- 5 分：能处理复杂系统、模型部署或工程化改造。

## 时间预算

- 1 分：1 天内，只适合内容选题或现成工具整理。
- 2 分：2 到 3 天，适合轻量 Demo。
- 3 分：3 到 7 天，适合 MVP 验证。
- 4 分：2 到 4 周，适合可用产品原型。
- 5 分：长期投入，适合 SaaS 或企业方案。

## 风险偏好

- 保守：优先低风险、低侵权、低合规压力。
- 中等：可接受 License 不确定或部署复杂，但需标注。
- 进取：可探索更复杂机会，但不能越过安全和违法边界。
